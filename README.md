# Berryloop Subscription Management System

Built for the Odoo x Make-A-Ton 9.0 Hackathon 2026.

Berryloop runs the full life of a subscription business in one place: products and plans,
subscriptions, invoices with taxes and discounts, payments, and a dashboard for the finance lead.
Customers get a read-only portal to see their own subscriptions and invoices.

## Features

| Area | What it does | Who |
|---|---|---|
| Accounts | Register (customers), log in and out, password rules (9+ characters with upper, lower and special), forgot and reset password by email | Everyone |
| Staff accounts | Admin adds staff members | Admin |
| Customers | Create, search, edit, view; link a customer to a login; delete (blocked if the customer has subscriptions) | Admin, staff (delete: admin) |
| Products | Name, description, status; search and filter; delete blocked if plans exist | Admin, staff (delete: admin) |
| Plans | Price, currency, billing interval (daily to yearly), status; search and filter; delete blocked if subscriptions use it | Admin, staff (delete: admin) |
| Subscriptions | Create for an active customer on an active plan; next billing date calculated; cancel, expire or reactivate | Admin, staff |
| Invoices | Generate from a subscription; subtotal, discount, tax and total calculated; numbered `INV-<year>-<id>`; overdue calculated from due date; mark as paid | Admin, staff |
| Tax rules | Percentage rules added to every new invoice while active | Admin sets, staff view |
| Discount rules | Fixed or percentage, whole subscription or one product; date range and usage limit; applied automatically to new invoices | Admin sets, staff view |
| Payments | Record payments with method, amount, date and note; partial payments; invoice becomes paid when the balance reaches zero | Admin, staff |
| Dashboard | Total customers, active subscriptions, monthly recurring revenue per currency, pending, overdue and paid invoices, recent subscriptions and invoices | Admin, staff |
| Customer portal | Read-only list of own subscriptions and invoices | Customer |
| Settings | Tax rules, discount rules, add staff | Admin (staff can view rules) |

### Not built yet
- Quotations and quotation templates
- The full Draft → Quotation → Confirmed → Active → Closed lifecycle (current statuses are active, cancelled and expired)
- Pause and renew for plans, and automatic closing at plan end date
- Product variants with price adjustments
- Sending and printing invoices
- Reports with filters, and a verified under-2-second response time for large data sets
- Automatic recurring billing (invoices are generated by hand from a subscription)
- Real payment gateway (payment status is recorded manually)

## Tech stack
- **Frontend:** React 18 + Vite 6 + react-router-dom 6 (in `frontend/`)
- **Backend:** Django 5.2 + Django REST Framework on Python 3.12 (in `backend/`)
- **Database:** PostgreSQL
- **Auth:** token authentication, roles `admin`, `staff`, `customer`, enforced on the server

## Project layout
```
backend/
  accounts/       users, roles, register/login/logout, staff creation, password reset
  customers/      customer records and their login links
  products/       products and plans
  subscriptions/  subscriptions, invoices, payments, tax and discount rules, dashboard summary
  config/         settings and root URLs
frontend/
  src/pages/      one page per screen (customers, products, plans, subscriptions, invoices, settings, portal, dashboard)
  src/billing.js  shared helpers for the billing pages
  src/customers.css  shared table, form and badge styles
docs/             project brief and architecture notes
```

## API overview
All endpoints are under `/api/`. Every request except register, login and password reset needs `Authorization: Token <token>`.

- Auth: `auth/register/`, `auth/login/`, `auth/logout/`, `auth/me/`, `auth/staff/`, `auth/password-reset/`, `auth/password-reset/confirm/`
- Customers: `customers/`, `customers/<id>/`, `customers/linkable-users/`
- Products: `products/`, `products/<id>/`, `products/options/`
- Plans: `plans/`, `plans/<id>/`
- Subscriptions: `subscriptions/`, `subscriptions/<id>/`
- Invoices: `invoices/`, `invoices/<id>/`, `invoices/<id>/mark-paid/`
- Payments: `payments/`, `payments/?invoice=<id>`
- Rules: `tax-rules/`, `discount-rules/` (and `<id>/`)
- Dashboard: `dashboard/summary/`

## Local setup (Windows PowerShell)

Prerequisites: Python 3.12, Node.js 20+ (LTS), PostgreSQL 16+.

### 1. Create the database
Open PostgreSQL's `psql` and run:

    CREATE USER berryloop WITH PASSWORD 'choose-a-password';
    CREATE DATABASE berryloop OWNER berryloop;

### 2. Backend
    cd "C:\Users\M S I\OneDrive\Desktop\berryloop\backend"
    py -3.12 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    copy .env.example .env
    # Open backend\.env and set POSTGRES_PASSWORD and DJANGO_SECRET_KEY
    python manage.py migrate
    python manage.py test
    python manage.py createsuperuser
    python manage.py runserver

The API runs at http://127.0.0.1:8000/api/health/ and the Django admin at http://127.0.0.1:8000/admin/.

Password reset emails print to this terminal in development. Copy the link from the output to reset a password.

### 3. Frontend (second PowerShell window)
    cd "C:\Users\M S I\OneDrive\Desktop\berryloop\frontend"
    npm install
    npm run build
    npm run dev

Open http://localhost:5173 in your browser.

If `Activate.ps1` is blocked, run once: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

### Demo walkthrough
1. Log in as admin.
2. Customers → add a customer. To give them a portal login, edit the customer and choose a customer login.
3. Products → add a product. Open it and add a plan (Plans → Add plan).
4. Settings → add a tax rule and, optionally, a discount rule.
5. Subscriptions → New subscription: pick the customer and plan.
6. Open the subscription → Generate invoice. Open the invoice → record a payment.
7. Dashboard shows the live figures.
8. Log in as the linked customer to see the read-only portal.

## Database migrations
Each app has its own migrations folder. After changing a model, run `python manage.py makemigrations <app>` and commit the new files in `migrations/`. Commit the migration files for `customers`, `products` and `subscriptions`; a fresh clone cannot run `migrate` without them.

## Security notes
- Never commit `backend/.env` or real passwords. `.gitignore` excludes them.
- Role checks happen on the server (`accounts/permissions.py`, `customers/permissions.py`, `products/permissions.py`, `subscriptions/permissions.py`), not only in the React app.
- Password reset returns the same message whether or not the email has an account.
- Customers can only read their own subscriptions and invoices; they cannot change anything.

## Testing
Run the backend suite with `python manage.py test` from the `backend` folder. The frontend build is `npm run build` from the `frontend` folder.
